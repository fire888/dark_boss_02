# Проект

3D-адвенчура на Three.js + TypeScript + webpack. Код разбит на главы `src/chapterNN`.
Текущий ствтус делаем главу 03.
**Актуальная база — `chapter10`.** Главы 04–09 — предыдущие итерации; переносить оттуда
паттерны можно только осознанно, конвенции там устарели.

Общее ядро — `src/_CORE`. Математика и сборка геометрии — `src/_CORE/_M/_m.ts`, импортируется как `_M`.

## Команды

```
npm run dev03            # dev-сервер chapter03
npm run build03          # прод-сборка chapter03
npx tsc --noEmit         # типы
npm run check:geom -- <путь-к-модулю> [экспорт] [--runs=N] [--args='[...]']
```

## Контракт геометрии

Геометрия строится линейными массивами чисел и возвращается фабрикой, а не собирается в меш.
Режима два, и числа в них разные — сначала определи, в каком работаешь.

### Неиндексированный — `src/chapter10/geometry`

**chapter10 не использует `index`**, только triangle soup. Возврат — `IArrayForBuffers`.

**Квад — это 6 вершин, не 4.** Числа, на которых легче всего ошибиться:

| вызов | длина | смысл |
|---|---|---|
| `_M.createPolygon(p0,p1,p2,p3)` | 18 | 6 вершин × xyz (2 треугольника) |
| `_M.createUv(a,b,c,d)` | 12 | 6 пар uv |
| `_M.fillColorFace([r,g,b])` | 18 | 6 вершин × rgb |

Отсюда инварианты: `c.length === v.length`, `uv.length === v.length / 3 * 2`, `v.length % 9 === 0`.

### Индексированный — `src/geometry`

Отдельное семейство модулей (`04_tunnel00`, `04_tunnel01`, `05_room00`), которое собирает
подземелье `chapter03`. Возврат — `IArraysGeom` (`{ index, v, c }`) из `_CORE/_M/_m`,
опции одним объектом с `DEFAULT_OPTS`, экспорт по имени файла (`tunnel01`, а не `createTunnel01`).
Импорт — от `baseUrl: ./src`: `import { tunnel01 } from 'geometry/04_tunnel01/tunnel01'`.

**Квад — это 4 вершины и 6 индексов**, `ind, ind+1, ind+2, ind, ind+2, ind+3`:

| массив | на квад | на треугольную грань |
|---|---|---|
| `v` | 12 (4 вершины × xyz) | 9 |
| `c` | 12 | 9 |
| `index` | 6 | 3 |

Инварианты: `c.length === v.length`, `index.length % 3 === 0`, `Math.max(...index) + 1 === v.length / 3`.
Последний — не косметика: висячая вершина, на которую не ссылается ни один индекс, ломает не рендер,
а склейку, потому что `_M.mergeIndexedArrays` берёт смещение как `max(index) + 1`, а не как длину `v`,
и следующий кусок наложится на предыдущий. Все три проверяет `_M.debugArrays`, то есть `check:geom`
их ловит сам.

Чего `check:geom` на индексированном модуле не делает: счётчик треугольников в его отчёте
(`v.length / 9`) и поиск вырожденных треугольников шагают по `v` девятками и про `index` не знают —
число «tris» врёт (реальное `index.length / 3`), а вырожденные ищутся в несуществующих тройках.
Направление обхода граней не проверяется ни в одном режиме, поэтому нормали и совпадение
с предыдущей реализацией проверяй отдельным прогоном.

### Жёсткие правила

- **Не сваривать вершины между гранями.** `_M.createBufferGeometry` всегда вызывает
  `computeVertexNormals()`; вершина, общая у двух граней, даст сглаженный стык вместо плоского.
  Дублирование вершин на грань — намеренное. Внутри одной плоской грани сварка допустима:
  два треугольника квада компланарны. В chapter10 это ни на что не влияет — там triangle soup
  без `index`, и квад остаётся 6 вершинами; в индексированных модулях (`src/geometry`)
  квад — 4 вершины и 6 индексов `0,1,2, 0,2,3`.
- **Фабрики должны быть чистыми и сериализуемыми.** Никаких `Mesh`, `Material`, `Texture`, DOM,
  обращений к `Root`. Разрешена только математика (`THREE.Vector2/Vector3`, `Matrix4`) и массивы чисел.
  Причина: `src/chapter10/entityLab01/geomWorkerFile.ts` исполняет их внутри Web Worker
  поверх SharedArrayBuffer, где рендерера нет. Это же свойство позволяет проверять их в Node.
- **UV только из `src/chapter10/geometry/tileMapWall.ts`** (`UV_EMPTY`, `UV_TRIANGLE`, `UV_POINTS`,
  `UV_DARK`, `UV_GRID`, `UV_GRID_CIRCLE`, `UV_HT`, `UV_POINTS_TREE`). Атлас рисуется процедурно
  в `src/chapter10/entities/TexturesCanvas.ts` (1024×1024, сетка 4×4, заняты только две верхние строки).
  Новая `UV_*` константа без парной правки `TexturesCanvas.ts` даст пустой тайл.
- **`_M` и `IArrayForBuffers` — только из `_CORE/_M/_m`.** В `chapter09/geometry/_m.ts` лежит
  устаревший форк, новый код на него не ссылается.
- **Импорты типов помечать `type`**: `import { _M, type IArrayForBuffers } from "_CORE/_M/_m"`.
  Без пометки Node не сможет загрузить модуль и `check:geom` не запустится.
- **`vCollide` — упрощённый прокси для физики**, а не копия рендер-геометрии. Длина кратна 9.
- **Задание про геометрию по умолчанию касается только видимой геометрии** — `v`, `uv`, `c`,
  `index`. Если в задаче сказано «разрежь», «добавь граней», «поменяй форму» без упоминания
  физики, `vCollide` не трогаем: он остаётся тем же грубым коробом. Правки прокси заказываются
  отдельно, и в тексте задачи будет прямо сказано, что речь о физике или о `vCollide`.

### Форма модуля chapter10

`src/chapter10/geometry/<имя>/<имя>.ts`, экспорт `create<Имя>`, возврат `IArrayForBuffers`.
(Форма индексированного модуля `src/geometry` описана выше и отличается — другое имя экспорта
и другой тип возврата.)
Композиция — через `_M.fill(src, dest)` + `_M.translateVertices` / `_M.rotateVerticesX/Y/Z`,
а не копированием кода. Разнообразие — `Math.random()`: один `mode`/`TYPE` на инстанс выбирает
семейство текстур, дальше вариации по граням внутри семейства.

Готовые модули как образец: `tree00`, `column02`, `arc00`, `helix00`, `platform00`.
Композитный пример — `waySystem/waySingle.ts`.

## Проверка результата

После любой правки геометрии:

```
npm run check:geom -- src/chapter10/geometry/<имя>/<имя>.ts
```

Валидатор запускает фабрику 20 раз (фабрики рандомизированы), прогоняет `_M.debugArrays`
и добавляет проверки на NaN, UV вне `[0,1]`, цвета вне `[0,1]`, вырожденные треугольники,
кратность `vCollide`, соответствие bbox заявленным `w/h/d`. Ненулевой код возврата = провал.

Утверждать, что геометрия работает, можно только после зелёного `check:geom`.
