# Проект

3D-адвенчура на Three.js + TypeScript + webpack. Код разбит на главы `src/chapterNN`.
Текущая задача пока не поставлена — будет поставлена позже.

Общее ядро — `src/_CORE`. Чистая математика и сборка геометрии — `src/_CORE/_M/_gm.ts`, импортируется как `_GM`.
Нечистые хелперы рендера и стенда (`Mesh`, `BufferGeometry`, DOM) — `src/_CORE/_M/_helpers.ts`, импортируется как `_H`.

## Команды

```
npx tsc --noEmit         # типы
npm run check:geom -- <путь-к-модулю> [экспорт] [--runs=N] [--args='[...]' | --args=@file.json]
```

`--args='[...]'` — только в bash: PowerShell и cmd срезают внутренние кавычки, и JSON до валидатора
не доходит. В них аргументы передаются файлом: `--args=@file.json` (JSON-массив аргументов фабрики).

## Контракт геометрии

Геометрия строится линейными массивами чисел и возвращается фабрикой, а не собирается в меш.

### Индексированный — `src/geometry`

**Эталон — `src/geometry/07_stairs00/stairs00.ts`.** Новый модуль строится по его образцу:
раскладка граней, хелперы `quad`/`fanTri`, запечённый свет, AO, прокси. Старые модули лежат
в `src/_00trash_geometry` — паттерны из них не переносить.

Возврат — `IBuffersGeom` из `_CORE/_M/_gm`, **все шесть массивов обязательны** — тип их и требует
(`IArraysGeom` — обязателен только `v`, остальные поля необязательны — остаётся для `_GM.mergeIndexedArrays` и стенда):
`{ index, v, uv, uv2, c, vCollide }`. Опции — тип `T` со всеми полями необязательными,
`DEFAULT_OPTS: Required<T>`, слияние `{ ...DEFAULT_OPTS, ...opts }`; положение — опция `pos: A3`.
Экспорт по имени файла (`stairs00`, а не `createStairs00`).
Импорт — от `baseUrl: ./src`: `import { stairs00 } from 'geometry/07_stairs00/stairs00'`.

**Квад — это 4 вершины и 6 индексов**, `ind, ind+1, ind+2, ind, ind+2, ind+3`, где `ind = v.length / 3`
берётся до push в `v`:

| массив | на квад | на треугольную грань | откуда |
|---|---|---|---|
| `v` | 12 (4 вершины × xyz) | 9 | |
| `uv` | 8 (4 пары) | 6 | атлас цвета `atlases/atlas00/atlas00`: `UV_*_Q`, внутри тайла — `_GM.rectPoint(RECT_*, s, q)` |
| `uv2` | 8 | 6 | атлас затенения `atlases/atlasAo00/atlasAo00`: `UV_AO_*_Q`, `_GM.flipUvQ`, `_GM.rectPoint(RECT_AO_*, …)` |
| `c` | 12 | 9 | запечённый свет `lit(base, nrm)`, не константа |
| `index` | 6 | 3 | |

`vCollide` — **без индекса**, triangle soup: длина кратна 9, квад прокси — 18 чисел
(`_GM.createPolygon`). Индексировать его нельзя: физика читает его девятками.

Инварианты: `c.length === v.length`, `uv.length === uv2.length === v.length / 3 * 2`,
`index.length % 3 === 0`, `Math.min(...index) === 0`, `Math.max(...index) + 1 === v.length / 3`, `vCollide.length % 9 === 0`.
Висячая вершина, на которую не ссылается ни один индекс, ломает не рендер, а склейку:
`_GM.mergeIndexedArrays` берёт смещение как `max(index) + 1`, а не как длину `v`.

#### Как устроен эталон

- **Грань — вызов хелпера.** `quad(a, b, cc, dd, nHint, uvQ, uv2Q, base, nrmAt?)`: a, b — низ тайла,
  cc, dd — верх, своя четвёрка вершин на каждую грань. Обход выбирается по нормали-подсказке `nHint`
  (`facesTo`), руками его не выписывают. При смене обхода b и dd меняются местами **вместе со своими
  `uv` и `uv2`**, иначе ориентированный тайл ляжет транспонированным. Неквадная грань (веер площадки) —
  `fanTri` с тем же правилом.
- **Цвет вершин — запечённый свет**, чтобы форма читалась на `MeshBasicMaterial`:
  `min(1, base × (AMBIENT + DIFFUSE · max(0, n·LIGHT)))`, `LIGHT` нормирован. Тайл атласа нейтральный,
  оттенок даёт `base` — опции модуля (`colWall`, `colStep`, `colTop`). У плоской грани `n` — её нормаль,
  у изогнутой (`radOut`/`radIn`) — нормаль в самой вершине: тогда изгиб виден без источника света.
- **`uv2` — затенение** (aoMap) двух случаев:
  - **внутренний угол** — низ внутренней стенки и подступенков над проступью, проступь у следующего
    подступенка, площадка у парапета;
  - **низ геометрии, который будет примыкать к земле** — низ наружной стенки, торцов, нижнего подступенка.

  Такая грань получает `UV_AO_TOP_Q` (тень на ребре cc, dd) или `_GM.flipUvQ(UV_AO_TOP_Q)` (на ребре a, b)
  — тенью к ребру угла или к нижнему ребру. Открытые грани — `UV_AO_NONE_Q`.
- **Ширина тени у угла одинакова с обеих сторон.** Тайл AO растягивается на грань, так что тень
  в метрах — доля тайла × размер грани поперёк ребра. Две грани одного угла должны ложиться на тайл
  в одном масштабе. В эталоне площадка у парапета — кольцо шириной `hW` с `UV_AO_TOP_Q`, как внутренняя
  стенка высотой `hW`; веер внутри кольца — `AO_NONE`. Если кольцо доходит до центра, веер получает
  `_GM.rectPoint(RECT_AO_TOP, .5, q)` с `q = 1 - rTop / hW` в центре.
  На материале — `aoMap` с `channel = 2` (three 0.173), пример — `src/ch_redactor/index.ts`.
- **Развёртка внутри тайла** — `_GM.rectPoint(RECT_*, s, q)` с `s, q`, зажатыми в `[0, 1]`: площадка
  целиком проецируется в один тайл и не вылезает в соседний.
- **Разнообразие** — один `TYPE` на инстанс (`Math.random()`) выбирает семейство (камень / мох),
  дальше редкие вариации по граням внутри семейства.
- **Прокси** строится отдельным проходом со своим, более грубым шагом (`arcStepCollide`) и проще
  по форме: пандус вместо ступеней, стенка без крышки и торцов.

#### Атласы

Хелперы атласов — в `_GM` (`_CORE/_M/_gm`), тип региона `T_TileRect`: `_GM.tileRect(size, x, y, w, h)` — регион в пикселях с отступом 2 px,
`_GM.rectUvQ` (8 чисел: a, b — низ тайла, c, d — верх), `_GM.flipUvQ`, `_GM.rectPoint`.

- `atlas00` — цвет, `512.jpg`, сетка 64 px: `RECT_WHITE`, `RECT_MOSS`, `RECT_RED`, `RECT_GRAY`, `RECT_GRAY_WIDE`.
- `atlasAo00` — затенение, `512Ao.jpg`: `RECT_AO_NONE`, `RECT_AO_TOP`, `RECT_AO_TOP_BOTTOM`, `RECT_AO_ROUND`.

На каждый тайл — тройка `RECT_*`, `UV_*`, `UV_*_Q`. Новый тайл — дорисовать его в jpg и добавить тройку
в модуль атласа. `check:geom` сверяет uv с экспортами `RECT_*`, так что регион без `RECT_*` он отвергнет.

#### Склейка

`_GM.mergeIndexedArrays(target, part)` сдвигает `index` и дописывает `v`, `uv`, `uv2`, `c`, `vCollide`.
Массив дописывается, только если он есть **у обоих** аргументов, поэтому `target` заводить со всеми шестью:
`{ index: [], v: [], uv: [], uv2: [], c: [], vCollide: [] }`, иначе массив молча потеряется.
Сдвиг части перед склейкой — `_GM.translateVertices` отдельно по `v` и по `vCollide`.

### Пользовательская — `src/geometryCustom`

Служебная геометрия под конкретное место в коде (например, `arrow` — стрелка для отладки управления).
В склейке с фабриками `src/geometry` не участвует. Возврат — `IArraysGeom`: обязателен только `v`.
Контракт индексированного режима, эталон и `check:geom` к ней не применяются. Новые фабрики уровня
сюда не кладут — они идут в `src/geometry`.

### Жёсткие правила

- **Не сваривать вершины между гранями.** Вершина несёт атрибуты своей грани: `uv` — точку в её тайле,
  `uv2` — AO, повёрнутый к её ребру, `c` — свет, запечённый от её нормали. Общая вершина двух граней
  может хранить только одно значение каждого атрибута, и соседняя грань получит чужой тайл, чужую тень
  и чужой свет. Второе следствие — на освещаемом материале: `_H.createBufferGeometry` всегда вызывает
  `computeVertexNormals()`, и общая вершина сгладит стык (на `MeshBasicMaterial` нормали не читаются).
  Дублирование вершин на грань — намеренное. Внутри одной плоской грани сварка допустима:
  два треугольника квада компланарны, квад — 4 вершины и 6 индексов `0,1,2, 0,2,3`.
- **Фабрики должны быть чистыми и сериализуемыми.** Никаких `Mesh`, `Material`, `Texture`, DOM,
  обращений к `Root`. Разрешена только математика (`THREE.Vector2/Vector3`, `Matrix4`) и массивы чисел.
  Причина: геометрия должна будет исполняться внутри Web Worker, где рендерера нет.
  Это же свойство позволяет проверять её в Node.
- **UV только из атласа.** `uv` из `atlases/atlas00/atlas00`, `uv2` из `atlases/atlasAo00/atlasAo00`
  (`UV_*_Q` или `_GM.rectPoint` внутри `RECT_*`); каждый треугольник целиком внутри одного региона.
- **`_GM`, `IBuffersGeom`, `IArraysGeom`, `A3` — только из `_CORE/_M/_gm`.** Рендер и стенд (`Mesh`,
  `BufferGeometry`, DOM) — `_H` из `_CORE/_M/_helpers`; фабрики его не импортируют. В `chapter09/geometry/_m.ts`
  лежит устаревший форк, `_00trash_geometry/GeomTypes` и `_00trash_geometry/atlasUv` — старое правило; новый код на них не ссылается.
- **Импорты типов помечать `type`**: `import { _GM, type IBuffersGeom, type A3 } from "_CORE/_M/_gm"`.
  Без пометки Node не сможет загрузить модуль и `check:geom` не запустится.
- **`vCollide` — упрощённый прокси для физики**, а не копия рендер-геометрии. Длина кратна 9.
- **Задание про геометрию по умолчанию касается только видимой геометрии** — `v`, `uv`, `uv2`, `c`,
  `index`. Если в задаче сказано «разрежь», «добавь граней», «поменяй форму» без упоминания
  физики, `vCollide` не трогаем: он остаётся тем же грубым прокси. Правки прокси заказываются
  отдельно, и в тексте задачи будет прямо сказано, что речь о физике или о `vCollide`.

## Проверка результата

После любой правки геометрии:

```
npm run check:geom -- src/geometry/<NN_имя>/<имя>.ts
```

Фабрика по умолчанию — экспорт с именем файла.
Валидатор запускает её 20 раз (фабрики рандомизированы), прогоняет `_GM.debugArrays`
и добавляет проверки на NaN, `uv`/`uv2`/цвета вне `[0,1]`, кратность `vCollide` (ERROR),
вырожденные треугольники и прокси не проще рендер-геометрии (WARN).
Кроме того:

- есть все шесть массивов `{ index, v, uv, uv2, c, vCollide }`, геометрия без `index` не принимается;
- треугольники и счётчик «tris» берутся из `index`;
- вершины не сварены между некомпланарными треугольниками (ERROR);
- каждый треугольник `uv` целиком внутри одного `RECT_*` из `atlas00`, `uv2` — из `atlasAo00` (ERROR);
- все цвета вершин одинаковы — свет не запечён (WARN).

Ненулевой код возврата = провал. Направление обхода граней валидатор не проверяет: в эталоне
оно задаётся нормалью-подсказкой, и ошибку в подсказке видно только на экране.

Утверждать, что геометрия работает, можно только после зелёного `check:geom`.
